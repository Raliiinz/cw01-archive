# Контрольная работа № 1 — Система архивирования

Сервис асинхронного архивирования файлов по HTTP(S)-ссылкам на базе Yandex Cloud. Принимает задание через HTTP API, помещает его в очередь, скачивает исходный файл, создаёт ZIP и сохраняет архив в Object Storage, а информацию о нём — в YDB.

## Архитектура

`POST /tasks` → API Gateway → Yandex Message Queue → триггер → Cloud Function (Python 3.12) → Object Storage + YDB.

API Gateway также обеспечивает получение списка архивов, метаданных отдельного архива и скачивание ZIP. Для неуспешных заданий предусмотрена dead-letter queue (DLQ).

Все облачные ресурсы, сервисные аккаунты, права, ключи доступа и таблица YDB создаются и удаляются через Terraform. Таблица YDB управляется Python-скриптом, который запускается Terraform локально.

## Требования

- Terraform **1.16.x или новее, но ниже 2.0** (используется `terraform_data.store`).
- Python **3.12** и `pip`.
- Yandex Cloud CLI (`yc`) с настроенным профилем и доступом к своему облаку.
- Права в выбранном каталоге, достаточные для создания сервисных аккаунтов, назначения IAM-ролей и управления используемыми сервисами Yandex Cloud; активный платёжный аккаунт и достаточные квоты.
- Доступ к сети для загрузки провайдеров и установки Python-зависимостей.

Закреплённые версии провайдеров: `yandex-cloud/yandex = 0.243.0` и `hashicorp/archive = 2.7.1`.

## Развёртывание

Все команды ниже выполняются из корня репозитория, если явно не указано иное.

### 1. Установить локальные Python-зависимости

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

**Важно:** не деактивируйте `.venv` перед `terraform apply` и `terraform destroy`: Terraform вызывает локальный `python scripts/ydb_table.py`, которому нужен `boto3`.

### 2. Авторизоваться в Yandex Cloud

Инициализировать CLI, если профиль ещё не создан:

```bash
yc init
```

Перед запуском Terraform установить переменную окружения с IAM-токеном:

```bash
export YC_TOKEN="$(yc iam create-token)"
```

Токен действителен не более 12 часов. При ошибке авторизации выполните команду повторно. Токен не требуется записывать в файлы проекта.

Узнать идентификаторы активного облака и каталога можно командами:

```bash
yc config get cloud-id
yc config get folder-id
```

При необходимости выберите в CLI профиль с нужным облаком и каталогом. Terraform использует `cloud_id` и `folder_id` из файла переменных, описанного ниже; они должны соответствовать доступному вам облаку и каталогу.

### 3. Указать только три входные переменные

```bash
cp terraform/terraform.tfvars.example terraform/terraform.tfvars
```

Откройте `terraform/terraform.tfvars` и замените образцы на **свои** значения:

```hcl
cloud_id    = "<cloud-id>"
folder_id   = "<folder-id>"
bucket_name = "vvot00-cw01-archives-unique1234"
```

Имя бакета должно быть **глобально уникальным** в Object Storage и начинаться с префикса вашей работы, например `vvot00-` или `vvot02-`. Префикс ресурсов вычисляется из части имени бакета до первого дефиса: для `vvot00-cw01-archives-unique1234` остальные ресурсы получат префикс `vvot00-`. Используйте только допустимые для Object Storage символы и нижний регистр.

Файл `terraform.tfvars` исключён из Git. Не добавляйте в репозиторий реальные токены и секретные ключи.

### 4. Создать инфраструктуру

```bash
cd terraform
terraform init
terraform validate
terraform plan
terraform apply
```

Подтвердите применение вводом `yes`. На пустом состоянии ожидается создание **24 ресурсов**. Terraform автоматически создаёт новую YDB, документную таблицу `archives`, бакет, очереди, функцию, триггер и API Gateway. При задержке готовности YDB скрипт создания таблицы делает повторные попытки.

Получить адрес API:

```bash
terraform output -raw api_gateway_url
```

Убедиться в отсутствии расхождений после создания:

```bash
terraform plan
```

Ожидаемый результат: `No changes. Your infrastructure matches the configuration.`

## Проверка работы API

Команды ниже выполняются из папки `terraform` после успешного развёртывания.

```bash
API_URL="$(terraform output -raw api_gateway_url)"
```

**1. Получить список архивов:**

```bash
curl -sS -i "$API_URL/archives"
```

Новая база возвращает HTTP `200` и `[]`.

**2. Создать задачу:**

```bash
curl -sS -i -X POST "$API_URL/tasks" \
  -H "Content-Type: application/json" \
  -d '{"name":"rfc1149.txt","url":"https://www.rfc-editor.org/rfc/rfc1149.txt"}'
```

Ожидается HTTP `202 Accepted`: задача принята, но архив создаётся **асинхронно**.

**3. Получить результат:**

```bash
curl -sS "$API_URL/archives" | python -m json.tool
```

Повторите чтение списка, если задача ещё обрабатывается. После завершения появится запись с полями `name`, `url` и `key`. Ключ архива — имя ZIP с UUID версии 7.

**4. Получить метаданные и ZIP:**

```bash
KEY="<key-из-ответа-GET-archives>"
curl -sS -i "$API_URL/archives/$KEY"
curl -f -sS -o /tmp/cw01-test.zip "$API_URL/download/$KEY"
unzip -t /tmp/cw01-test.zip
unzip -l /tmp/cw01-test.zip
```

Вместо `<key-из-ответа-GET-archives>` вставьте фактическое значение поля `key` без угловых скобок. Ожидаются HTTP `200` и ZIP, содержащий исходный файл `rfc1149.txt`.

В API также предусмотрены проверки некорректных заданий (`400`) и отсутствующих архивов (`404`). Неуспешные задания могут переходить из основной очереди в DLQ после превышения допустимого числа доставок.

## Автоматические тесты

Из корня репозитория с активированной `.venv`:

```bash
python -m unittest discover -s tests -v
```

В текущем наборе — 13 тестов для архивирования, обработчика, YDB, Object Storage и спецификации OpenAPI. Тесты не создают облачные ресурсы.

## Полное удаление инфраструктуры

Из папки `terraform`, **с активной `.venv` и действующим `YC_TOKEN`**:

```bash
terraform destroy
```

Подтвердите удаление вводом `yes`. Terraform удаляет документную таблицу YDB, остальные ресурсы и бакет вместе с архивами (`force_destroy = true`). **Все созданные архивы и метаданные будут потеряны.**

При необходимости проверить пустое состояние:

```bash
terraform state list
```

Ожидается пустой вывод.

## Безопасность и замечания

- `terraform/terraform.tfvars`, `*.tfstate*`, `.env*`, `.venv/` и создаваемые ZIP-файлы исключены из Git.
- Создаваемые Terraform статические ключи доступны ему в состоянии (`terraform.tfstate`), даже если в обычном выводе они помечены как чувствительные. **Не публикуйте Terraform State и файлы с секретами.**
- Архивный бакет закрыт для анонимного доступа. Скачивание осуществляется через API Gateway.
- Для публикации исходного проекта достаточно кода, примера переменных и `.terraform.lock.hcl`; собственные значения `cloud_id`, `folder_id`, токены и файлы состояния публиковать не нужно.
- Для установки провайдеров может потребоваться доступ к Terraform Registry. В конфигурации используется актуальный для проекта Python 3.12.
